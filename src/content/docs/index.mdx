## install it

```sh
npm install @sendust/ts
```

That's the whole setup — no Rust toolchain, no build step on your side.

Then it's one transport per process: `send()` queues, the engine keeps the
sessions the work needs, `close()` drains the rest. The runtime and platform
pins are in the [quick start](guide/quick-start/) — lowkey load-bearing, read
them.

<CardGrid>
  <Card title="queue + pool, automatic">
    Fire a hundred sends and it handles the vibe: up to `delivery.maxConcurrent`
    at once, over at most `delivery.maxConnections` native sessions, one SMTP
    transaction each. The queue is bounded, so the worst case is
    `LIMIT_QUEUE_FULL` — not an OOM. [lifecycle + limits](guide/lifecycle-limits/)
  </Card>
  <Card title="sessions stay warm">
    Definitive outcome → the session is reset and kept: up to
    `delivery.maxMessagesPerSession` messages or `delivery.sessionIdleMs` of
    idleness. Error or `unknown` → dropped. Reuse never turns an uncertain
    delivery into a double send. [lifecycle + limits](guide/lifecycle-limits/)
  </Card>
  <Card title="accepted ≠ delivered">
    `accepted` means the relay took responsibility, full stop. There's no
    `delivered`, `opened` or `bounced` status, and the lib never retries
    `unknown` — that call is yours. [errors, security, ops](guide/errors-security-operations/)
  </Card>
</CardGrid>
