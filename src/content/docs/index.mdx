## Install

```sh
npm install @sendust/ts
```

One transport per process. `send()` queues what you hand it, the engine keeps the
sessions the work needs, and `close()` drains the rest. The exact runtime and
platform requirements are in the [quick start](guide/quick-start/).

<CardGrid>
  <Card title="Autonomous queue and pool">
    Concurrent `send()` calls are accepted and scheduled, up to `delivery.maxConcurrent`
    at once over at most `delivery.maxConnections` native sessions, each running one SMTP
    transaction at a time. The queue is bounded, so it fails with `LIMIT_QUEUE_FULL`
    instead of exhausting memory. [Lifecycle and limits](guide/lifecycle-limits/)
  </Card>
  <Card title="Sessions reused across messages">
    After a definitive outcome the session is reset and kept, up to
    `delivery.maxMessagesPerSession` messages or `delivery.sessionIdleMs` of idleness.
    After an error, or an `unknown` disposition, it is dropped: reuse must never turn an
    uncertain delivery into a duplicated one. [ADR 0022](decisions/0022-session-reuse/)
  </Card>
  <Card title="Relay acceptance, not delivery">
    `accepted` means the relay took responsibility for the message. There is no
    `delivered`, `opened`, or `bounced` status, and `unknown` is never retried by the
    library. [Error model](api/error-model/)
  </Card>
</CardGrid>
